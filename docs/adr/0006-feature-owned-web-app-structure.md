# Feature-Owned Web App Structure

Coin Archive's web app will keep TanStack Router file routes in `apps/web/src/routes`, but route files should act as thin adapters around feature-owned behavior. User-facing product areas, starting with database maintenance, will live under `apps/web/src/features` with colocated page components, server functions, validation, UI, helpers, constants, and tests; shared app shell components and cross-feature infrastructure remain in `components` and `lib`. This was chosen over technical top-level folders or an all-at-once mass move because feature folders make related workflow changes easier to reason about while preserving routing conventions and allowing incremental migration, beginning with the Issuer maintenance slice.

Database maintenance pages will migrate one page at a time into one feature slice per page. Entity CRUD pages use `apps/web/src/features/database/<entity>-maintenance`, the database index page uses `apps/web/src/features/database/database-overview`, and route files export only TanStack Router adapters that import each feature's route loader and route component from the feature root `index.ts`. Each slice owns its page-specific tables, forms, sheets, validation, mutation helpers, server actions, loader logic, constants, and tests; shared authentication, collector-role, authorization, app shell, generic UI, and cross-feature infrastructure stay outside the slices.

Database-area navigation is shared by multiple database pages and menus, so it belongs to `apps/web/src/features/database/navigation.ts` rather than a private route file. Each feature root exposes only route-facing exports by convention and is protected by a public API guard test; feature internals should use relative imports instead of importing themselves through the `@/features/database/<feature>` alias.
