# Atomic Coin Maintenance Submissions

Coin Maintenance will save create and edit submissions as whole Coin aggregate transactions rather than section-by-section updates. A Coin editor can change core fields, ordered Ruler Attributions, Mint Attributions, Theme Attributions, Catalogue References, the Surface Set, and face-specific Engraver Attributions together, so committing the aggregate atomically keeps publishable catalogue entries from entering mixed partial states and lets validation reason about the full submitted record.

Database mutation APIs for Coin Maintenance should expose aggregate-level operations that create, update, or delete the Coin and its owned child records within one transaction. Updates replace owned child collections from the submitted form state and touch the parent Coin's `updatedAt` timestamp even when only child records changed, while lookup entities such as Issuers, Rulers, Mints, Themes, Catalogues, Engravers, Distributions, Compositions, Currencies, Orientations, Shapes, Minting Techniques, Edges, and Rims remain referenced records maintained by their own pages.
